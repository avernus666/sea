# SEA — атлас морских профессий

Образовательный сайт для школьников, абитуриентов, курсантов и людей, уже работающих в морской отрасли. Проект помогает изучить морские учебные заведения, сравнить направления подготовки, понять повседневную жизнь курсанта и составить реалистичный план подготовки со школы.

> **Важно:** каталог является редакционной стартовой подборкой, а не полным государственным реестром. Специальности, бюджетные места, сроки, медицинские требования, документы и правила приёма меняются. Перед подачей документов проверяйте их на официальном сайте конкретного учреждения и в приёмной комиссии.

## Возможности сайта

- Каталог морских университетов, институтов, колледжей и техникумов с поиском.
- В разделе «Учёба» размещена текстовая ссылка на официальную страницу Арктического морского института имени В. И. Воронина в Архангельске — без отдельной карточки в каталоге.
- Расширенная подборка учебных заведений с поиском и официальными сайтами; перед поступлением проверяйте актуальность программ.
- 12 тематических направлений: судовождение, энергетика, автоматика, логистика, кораблестроение, связь, гидрография, безопасность, экология и другие.
- Расширенные разделы: учебный набор, план поступления, морской словарь, курсантская жизнь и профессиональный рост.
- Подборка популярных направлений и учебных тем вынесена вперёд для удобного старта.
- Учебный маршрут от начальной школы до поступления и профессионального развития.
- Материалы о буднях курсантов: расписание, дисциплина, командная работа, тренажёры, практика и адаптация.
- Раздел для действующих специалистов: непрерывное обучение, безопасность, технические знания и профессиональный английский.
- Морской визуальный стиль, адаптивная вёрстка и изображения для погружения в тему.

## Технологический стек

| Область | Технологии | Назначение |
|---|---|---|
| Frontend | TypeScript, React, HTML5, CSS, Vite | Интерфейс, каталог и навигация |
| Основной backend | Go | REST API, бизнес-логика и доступ к данным |
| Дополнительный сервис | Python, FastAPI, Pydantic | Учебные маршруты и рекомендации по этапу обучения |
| База данных | PostgreSQL 16 | Хранение каталога и справочных данных |
| Контейнеризация | Docker, Docker Compose | Повторяемый запуск окружения |
| CI | GitHub Actions | Сборка frontend, тесты Go и Python |

Go — основной серверный язык проекта. FastAPI используется как небольшой отдельный вспомогательный сервис; Java/Spring Boot в текущей версии не используется.

## Архитектура и принципы проектирования

```text
Browser
  └── React + TypeScript (Vite)
        ├── Go REST API :8080
        │     └── repository interface
        │           └── PostgreSQL :5432
        └── FastAPI learning service :8081
```

### Go API

- `cmd/api` — composition root: создание конфигурации, соединения с БД, репозитория и HTTP-обработчиков.
- `internal/domain` — доменные модели без зависимости от HTTP и PostgreSQL.
- `internal/repository` — интерфейсы и PostgreSQL-реализация доступа к данным.
- `internal/httpapi` — HTTP-маршруты, валидация параметров, CORS и безопасные ответы.
- `migrations` — SQL-схема и начальные справочные данные.

### FastAPI

- `app/main.py` — отдельное приложение, Pydantic-схема ответа и маршруты учебного плана.
- `tests` — тесты health endpoint, результата учебного маршрута и проверки некорректного параметра.

### Применённые инженерные принципы

- **SRP:** HTTP, доменная модель, конфигурация и доступ к данным разделены.
- **DIP:** HTTP-слой Go зависит от интерфейса репозитория, а не от конкретного PostgreSQL-клиента.
- **Инкапсуляция:** реализация хранения не протекает в интерфейс API.
- **Валидация на границе:** параметры проверяются до выполнения запросов и формирования ответа.
- **Безопасность:** SQL-параметры передаются отдельно, ошибки БД не раскрываются клиенту, CORS ограничен разрешённым origin, добавлены базовые security headers.
- **Простота:** вспомогательный Python-сервис изолирован от основного Go API и может развиваться независимо.

SOLID в Go применяется через небольшие интерфейсы и композицию, а не через искусственные классы и абстракции. Не следует добавлять интерфейс, если у него нет реального потребителя или необходимости тестирования.

## Быстрый запуск через Docker

Требуется установленный Docker Desktop или Docker Engine с Compose Plugin.

```bash
cp .env.example .env
docker compose up --build
```

Адреса локального окружения:

- Сайт: `http://localhost:4173`
- Go API health: `http://localhost:8080/health`
- Каталог учреждений: `http://localhost:8080/api/v1/institutions`
- Поиск учреждений: `http://localhost:8080/api/v1/institutions?query=архангельск`
- FastAPI health: `http://localhost:8081/health`
- Документация FastAPI: `http://localhost:8081/docs`
- Учебный маршрут: `http://localhost:8081/api/v1/learning-path?grade=8`
- PostgreSQL: `localhost:5432`

Для остановки:

```bash
docker compose down
```

Для удаления также локального тома с данными (необратимо):

```bash
docker compose down -v
```

## Локальная разработка

### Frontend

```bash
cd frontend
npm install
npm run dev
npm run build
```

Vite выводит адрес разработки в терминал.

### Go API

Требуется Go 1.23+ и доступный PostgreSQL. Укажите `DATABASE_URL` и `ALLOWED_ORIGIN` в окружении.

```bash
cd backend
gofmt -w .
go test ./...
go run ./cmd/api
```

### FastAPI

Требуется Python 3.12+.

```bash
cd recommendation-service
python -m venv .venv
```

Linux/macOS:
```bash
source .venv/bin/activate
```

Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```

Затем:
```bash
pip install -r requirements.txt
pytest -q
uvicorn app.main:app --reload --host 0.0.0.0 --port 8081
```

## API-контракты

### Go API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | Проверка доступности API |
| GET | `/api/v1/institutions` | Список учреждений |
| GET | `/api/v1/institutions?query=...` | Поиск по каталогу |
| GET | `/api/v1/institutions/{id}` | Учреждение по идентификатору |

### FastAPI

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | Проверка доступности сервиса |
| GET | `/api/v1/learning-path?grade=8` | Учебный маршрут по этапу обучения |

Параметр `grade` принимает значения от 1 до 100. Это условный номер класса/этапа для подбора справочного плана, а не официальный критерий приёма.

## Образовательная логика

- **Начальная школа:** грамотность, математика, география, любознательность, командная работа и безопасное знакомство с морской тематикой.
- **5–9 классы:** математика, физика, информатика, география и английский; профориентация и изучение условий поступления.
- **10–11 классы:** профильные предметы по выбранной программе, документы, сроки и проверка официальных медицинских требований.
- **Студенты и взрослые:** профильные дисциплины, практическая подготовка, морской английский, охрана труда и развитие компетенций.

Нет единого обязательного списка предметов для всех мореходных заведений: ориентируйтесь на опубликованные правила приёма и учебный план конкретной программы.

## CI/CD

GitHub Actions запускает:

1. Установку Node.js и сборку TypeScript/React.
2. Установку Go, форматирование и `go test ./...`.
3. Установку Python и выполнение `pytest -q` для FastAPI.

Это CI-проверки, а не полноценный автоматический production-деплой. Для CD выберите целевой хостинг, добавьте отдельный workflow публикации образов и деплоя, настройте secrets в GitHub Environments, ручное подтверждение production и стратегию отката. Не храните production-пароли в репозитории.

## Переменные окружения

См. `.env.example`:

- `PORT` — порт Go API.
- `DATABASE_URL` — строка подключения Go API к PostgreSQL.
- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` — параметры контейнера PostgreSQL.
- `ALLOWED_ORIGIN` — разрешённый frontend origin для Go API.

Значения в примере предназначены только для локальной разработки. В production используйте секреты платформы, TLS, отдельного пользователя БД с минимальными правами и уникальные пароли.

## Перед production

- Подключить frontend к Go API для всех каталогов и удалить дублирование демонстрационных данных.
- Проверить миграции, индексы, таймауты соединений и graceful shutdown.
- Добавить rate limiting, централизованные логи, метрики, трассировку и резервное копирование PostgreSQL.
- Добавить интеграционные тесты с тестовой БД и контрактные тесты между сервисами.
- Уточнить источники и дату проверки каждой записи каталога.
- Проверить доступность сайта с клавиатуры, контрастность, мобильную вёрстку и альтернативные подписи изображений.
- Настроить TLS, мониторинг, обновление зависимостей, сканирование контейнеров и проверенный процесс отката.
